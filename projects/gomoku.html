Project Gomoku

Unity로 제작한 오목 기반 2인용 보드게임

프로젝트 소개

Project Gomoku는 전통 보드게임인 오목을 Unity로 구현한 2인용 보드게임 프로젝트입니다.

플레이어는 흑돌과 백돌을 번갈아가며 보드 위에 배치하고, 가로, 세로, 대각선 방향 중 하나로 같은 색 돌 5개를 먼저 연결하면 승리합니다.

단순한 규칙을 가진 게임이지만, 실제 구현에서는

보드 좌표 관리, 착수 가능 여부 판정, 턴 전환, 승리 조건 검사, UI 갱신, 게임 상태 관리가 정확하게 맞물려야 합니다.

이 프로젝트에서는 오목의 기본 규칙을 기반으로

플레이어 입력부터 돌 배치, 승패 판정, 게임 재시작까지 하나의 완성된 게임 흐름으로 구현하는 것을 목표로 했습니다.

게임 목표

플레이어는 흑돌과 백돌을 번갈아 배치하며,

먼저 같은 색 돌 5개를 연속으로 연결하는 것을 목표로 합니다.

승리 조건은 다음 네 방향을 기준으로 검사합니다.

  • 가로 방향
  • 세로 방향
  • 좌상단 ↔ 우하단 대각선
  • 우상단 ↔ 좌하단 대각선

핵심 게임 규칙

1. 턴제 진행

게임은 흑돌과 백돌이 번갈아가며 진행됩니다.

현재 차례의 플레이어가 보드 위에 돌을 배치하면,

해당 위치가 유효한지 검사한 뒤 다음 플레이어에게 턴이 넘어갑니다.

2. 돌 배치

플레이어는 비어 있는 칸에만 돌을 놓을 수 있습니다.

이미 돌이 놓여 있는 칸에는 다시 착수할 수 없으며,

보드 범위를 벗어난 위치에도 돌을 둘 수 없습니다.

3. 승리 조건

돌을 배치한 후에는 해당 돌을 기준으로 네 방향을 검사합니다.

같은 색 돌이 한 방향으로 연속해서 5개 이상 이어져 있다면 해당 플레이어가 승리합니다.

4. 게임 종료

승리 조건이 만족되면 게임은 종료 상태로 변경됩니다.

게임이 종료된 뒤에는 추가 착수를 막고,

승리한 플레이어를 UI에 표시하도록 구성했습니다.

주요 구현 내용

보드 시스템

오목 게임의 핵심은 보드 데이터를 정확하게 관리하는 것입니다.

각 칸은 좌표 기반으로 관리되며,

현재 칸이 비어 있는지, 흑돌이 놓여 있는지, 백돌이 놓여 있는지를 상태값으로 구분합니다.

구현한 주요 기능은 다음과 같습니다.

  • 보드 크기 관리
  • 좌표 기반 셀 접근
  • 셀 상태 저장
  • 착수 가능 여부 검사
  • 보드 초기화
  • 게임 종료 후 입력 제한

좌표 기반 돌 배치

플레이어가 보드 위를 클릭하면 해당 위치가 어떤 칸에 해당하는지 계산합니다.

계산된 좌표를 기준으로 다음 조건을 확인합니다.

  • 보드 범위 안에 있는 위치인지
  • 이미 돌이 놓여 있지 않은지
  • 게임이 진행 중인 상태인지

모든 조건을 만족하면 현재 턴의 돌을 해당 위치에 배치합니다.

턴 전환 시스템

오목은 두 플레이어가 번갈아 진행하는 턴제 게임입니다.

따라서 돌을 정상적으로 배치한 뒤에는 현재 턴 정보를 변경해야 합니다.

턴 시스템에서는 다음 요소를 관리했습니다.

  • 현재 플레이어 정보
  • 흑돌 / 백돌 구분
  • 착수 후 턴 전환
  • 게임 종료 시 턴 진행 중단
  • 현재 차례 UI 표시

승리 조건 검사

돌을 배치할 때마다 전체 보드를 매번 검사하는 방식보다,

방금 배치한 돌을 기준으로 필요한 방향만 검사하는 방식이 효율적입니다.

검사 방향은 다음 네 가지입니다.

  • 가로
  • 세로
  • 좌상단 ↔ 우하단 대각선
  • 우상단 ↔ 좌하단 대각선

각 방향에서 양쪽으로 같은 색 돌이 몇 개 이어져 있는지 확인하고,

합산 결과가 5개 이상이면 승리로 판정합니다.

게임 상태 관리

게임은 단순히 돌을 놓는 상태만 있는 것이 아니라,

현재 어떤 단계인지에 따라 입력과 UI 처리가 달라져야 합니다.

관리한 게임 상태는 다음과 같습니다.

  • 게임 대기
  • 게임 진행 중
  • 흑돌 턴
  • 백돌 턴
  • 승리 판정 완료
  • 게임 종료

이 상태값을 기준으로 불필요한 입력을 막고,

게임 흐름이 꼬이지 않도록 구성했습니다.

UI 시스템

플레이어가 현재 게임 상태를 쉽게 확인할 수 있도록 UI를 구성했습니다.

UI에서 표시하는 정보는 다음과 같습니다.

  • 현재 턴
  • 흑돌 / 백돌 구분
  • 승리한 플레이어
  • 게임 종료 메시지
  • 재시작 버튼

게임 상태가 변경될 때마다 UI도 함께 갱신되도록 구성했습니다.

재시작 기능

게임이 끝난 뒤 다시 플레이할 수 있도록 재시작 기능을 구현했습니다.

재시작 시에는 다음 정보가 초기화됩니다.

  • 보드에 놓인 모든 돌
  • 현재 턴 정보
  • 승리 상태
  • 게임 종료 상태
  • UI 메시지

이를 통해 씬을 다시 로드하지 않고도 새로운 게임을 시작할 수 있도록 구성했습니다.

구현하면서 신경 쓴 부분

1. 보드 데이터와 화면 표시 분리

보드의 실제 상태와 화면에 보이는 돌 오브젝트를 분리해서 관리했습니다.

게임 로직은 좌표 데이터와 상태값을 기준으로 처리하고,

화면에 보이는 돌은 그 결과를 시각적으로 표현하는 역할만 하도록 구성했습니다.

이 구조를 통해 게임 판정과 UI 표시가 서로 꼬이지 않도록 했습니다.

2. 승리 판정 최적화

승리 여부를 확인할 때 전체 보드를 매번 검사하는 방식은 비효율적일 수 있습니다.

그래서 방금 놓은 돌을 기준으로

가로, 세로, 대각선 방향만 검사하는 방식으로 구현했습니다.

이 방식은 오목의 규칙에 적합하며,

불필요한 연산을 줄이면서도 정확한 승리 판정이 가능합니다.

3. 중복 착수 방지

이미 돌이 놓인 칸에 다시 돌을 놓으면 게임 규칙이 깨질 수 있습니다.

따라서 착수 전 해당 좌표의 상태를 먼저 검사하고,

빈 칸일 때만 돌을 배치하도록 구성했습니다.

이를 통해 잘못된 입력으로 인한 게임 데이터 오류를 방지했습니다.

4. 게임 종료 후 입력 제한

승자가 결정된 이후에도 플레이어가 계속 돌을 놓을 수 있다면,

게임 상태와 결과가 어긋날 수 있습니다.

따라서 게임 종료 상태에서는 추가 입력을 받지 않도록 처리했습니다.

트러블슈팅

문제 1. 클릭 위치와 실제 보드 좌표가 어긋나는 문제

원인

마우스로 클릭한 화면 위치를 그대로 사용하면,

실제 보드의 칸 좌표와 정확히 일치하지 않는 문제가 발생할 수 있었습니다.

해결

화면 좌표를 보드 기준 좌표로 변환한 뒤,

셀 크기를 기준으로 몇 번째 칸인지 계산하도록 처리했습니다.

이를 통해 플레이어가 클릭한 위치와 실제 돌이 놓이는 위치가 일치하도록 만들었습니다.

문제 2. 이미 돌이 있는 칸에 다시 둘 수 있는 문제

원인

돌을 배치하기 전에 해당 칸의 상태를 검사하지 않으면,

기존 돌 위에 새로운 돌이 덮이는 문제가 발생할 수 있습니다.

해결

착수 전 보드 데이터에서 해당 좌표의 상태를 확인하고,

비어 있는 칸일 때만 돌을 배치하도록 수정했습니다.

문제 3. 대각선 승리 판정이 누락되는 문제

원인

가로와 세로는 단순한 좌표 증가로 검사할 수 있지만,

대각선은 x와 y 좌표가 동시에 변하기 때문에 별도 방향 검사가 필요했습니다.

해결

대각선 방향을 두 가지로 나누어 검사했습니다.

  • x + 1, y + 1 방향
  • x + 1, y - 1 방향

각 방향의 양쪽을 모두 확인하여 연속된 돌 개수를 합산하도록 처리했습니다.

문제 4. 승리 후에도 턴이 넘어가는 문제

원인

승리 판정 후에도 기존 턴 전환 로직이 실행되면,

게임이 종료되었음에도 다음 플레이어 턴으로 표시되는 문제가 발생할 수 있습니다.

해결

돌을 배치한 뒤 먼저 승리 조건을 검사하고,

승리하지 않았을 때만 턴을 전환하도록 흐름을 정리했습니다.

구현을 통해 배운 점

이번 프로젝트를 통해 보드게임 구현에서 가장 중요한 것은

단순히 오브젝트를 화면에 배치하는 것이 아니라,

보드 데이터와 게임 규칙을 정확하게 관리하는 것이라는 점을 배웠습니다.

오목은 규칙 자체는 단순하지만,

실제로 구현하려면 좌표 관리, 턴 전환, 중복 입력 방지, 승리 조건 검사, 게임 종료 상태 관리가 모두 필요했습니다.

특히 승리 판정 로직을 구현하면서

2차원 배열 기반 보드에서 방향 벡터를 활용해 특정 패턴을 검사하는 방법을 익힐 수 있었습니다.

또한 게임 상태를 명확하게 분리해두면

입력 처리, UI 갱신, 턴 전환이 더 안정적으로 동작한다는 것을 경험했습니다.
